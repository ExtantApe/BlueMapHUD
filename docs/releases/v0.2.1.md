A small release: you can now choose which address the built-in pack server listens on.

## New

- **`pack.bind`.** The address the pack server listens on. Empty, the default, listens on every address, as before. `127.0.0.1` keeps it on the server's own machine: use that when players get the pack another way (`pack.public-url`, or `pack.send: false` with the files merged into your own pack), so the port is never open to the network. Anything that isn't an IP address stops the pack server, with a console line saying why, rather than falling back to every address.

## Upgrading

Replace the jar. `config.yml` gains `pack.bind: ""`, which changes nothing until you set it. The commands and permissions 0.2.0 marked as deprecated are still here; they go in 0.3.0, not in this patch release.

## Tested

- 4 new unit tests: empty means every address, IPv4 and IPv6 loopback stay local, names and typos are refused, and a real server listens only where told.
- The live suite now runs with `pack.bind: 127.0.0.1`, so every pack download in it went through the loopback-only server. A new check confirms the port answers on 127.0.0.1 and is refused on the machine's own network address. The live suite passed 335/335 on Paper 26.1.2 (one font check skipped, as before, without a client classpath). Not run on 26.2 or 26.3 for this release.
